# Data Card — BirdStrikeGeo

This document describes every dataset BirdStrikeGeo uses or is designed
to use: what it is, where it comes from, what its known limitations are,
and how this project handles those limitations in code.

---

## 1. FAA Wildlife Strike Database

- **What it is:** individual reports of wildlife strikes to U.S. civil
  aircraft, submitted voluntarily by pilots, airports, and airlines to
  the FAA.
- **Used for:** Task A (reported-strike damage prediction) — the only
  required data source for that task.
- **Known limitations:**
  - **Reporting is voluntary and incomplete.** The database is not a
    census of all strikes that occur; it reflects what was reported.
    Any model trained on it inherits this reporting bias.
  - **Damage outcome is sometimes missing or ambiguous.** This project
    only builds a supervised target from *explicit* `damage_flag`
    values (see `birdstrikegeo/features/build_damage_features.py`) and
    excludes — never guesses — rows where the outcome isn't clear
    (reported separately in the data-quality report).
  - **Column names vary across export vintages.** Handled via
    alias-based resolution (`birdstrikegeo/data/column_aliases.py`),
    which refuses to guess when a column is genuinely ambiguous.
- **Real download:** see `DATA_DOWNLOAD_GUIDE.md`.
- **Sample fixture:** `data/sample/faa_strikes_sample.csv` — 500
  synthetic rows using realistic raw-export-style column names,
  generated by `scripts/generate_sample_data.py`. **Not real strike
  data.**

## 2. Trektellen

- **What it is:** a bird-migration monitoring network (Dutch-led,
  primarily European with some global sites) where volunteer observers
  log visible migration counts, captures, and nocturnal flight calls at
  fixed monitoring sites.
- **Used for:** Task B (airport-period wildlife activity index).
- **Known limitations:**
  - **Sites are not uniformly distributed.** Many regions — including
    most U.S. airports — have no nearby monitoring site at all. This
    project surfaces that explicitly (`trektellen_available`,
    `distance_warning`, `low_coverage_warning` — see
    `birdstrikegeo/features/build_activity_features.py`) rather than
    interpolating confidently across large gaps.
  - **Observer effort varies** session to session and site to site.
    `observation_hours` and `observer_effort_available` are preserved
    and used to effort-normalize activity features
    (`birds_per_observation_hour_previous_7d`).
  - **Count types measure different things.** Visible migration counts,
    captures, and nocturnal flight calls are different observational
    processes and are never silently summed together — `count_type` is
    preserved and features either filter to one type or explicitly
    document combining them.
  - **A missing observation is not zero activity.** The absence of a
    monitoring session in a time window is reported as `None`
    (unknown), never as `0` — see `_windowed_total()` in
    `build_activity_features.py`.
- **Access requirements:** this project **never scrapes Trektellen**.
  Real data requires a user-authorized export and a completed
  provenance record (`TREKTELLEN_PROVENANCE_FIELDS` in
  `birdstrikegeo/schemas/trektellen.py`) — see `DATA_DOWNLOAD_GUIDE.md`.
- **Sample fixture:** `data/sample/trektellen_sites_sample.csv` (40
  synthetic sites) and `trektellen_counts_sample.csv` (~5,000 synthetic
  count rows), plus `trektellen_provenance_sample.json`, explicitly
  marked as a synthetic fixture, not a real authorized export.

## 3. Airports

- **What it is:** airport point locations and metadata (ICAO/IATA
  codes, runway info, etc.).
- **Used for:** airport-centered geospatial features (Trektellen
  proximity, buffers). Optional — FAA-reported lat/lon on individual
  strikes can be used directly without this dataset.
- **Real download:** `data/raw/airports.csv`, sourced from OurAirports
  (public domain, see `DATA_DOWNLOAD_GUIDE.md`) — downloaded 2026-09-06,
  86,051 airports worldwide. **Not yet wired into the pipeline** — column
  names don't match `AIRPORT_SCHEMA` yet; see `DATA_DOWNLOAD_GUIDE.md`
  for the exact mapping needed. See also `ESRI_DISCUSSION_NOTES.md`
  question 15 for whether a different/complementary source (e.g. an Esri
  Living Atlas airport layer) would be preferable for a real publish.
- **Sample fixture:** `data/sample/airports_sample.geojson`/`.csv` — 25
  synthetic airport points (15 in a CONUS-like bounding box, 10 in a
  Europe-like bounding box), clearly named `(SYNTHETIC)`.

## 4. Hourly weather

- **What it is:** station-based hourly weather observations (e.g. NOAA
  ISD/METAR-derived).
- **Used for:** optional weather features joined to strikes/activity
  queries via nearest-station, nearest-prior-hour matching
  (`birdstrikegeo/geo/temporal_join.py`). Never uses a future
  observation by default.
- **Known limitations:** station coverage is uneven; a distant or stale
  match is recorded as such (`weather_station_distance_km`,
  `weather_observation_age_minutes`, `weather_available`) rather than
  silently used regardless of quality.
- **Real download:** see `DATA_DOWNLOAD_GUIDE.md`.
- **Sample fixture:** `data/sample/weather_sample.csv` — 14 days of
  hourly synthetic weather at each sample airport.

## 5. BTS T-100 departures (future / not yet used)

- **What it is:** U.S. Bureau of Transportation Statistics flight
  segment/departure data.
- **Why it's here:** a defensible non-strike "exposure" denominator
  (how many flights actually occurred) is a prerequisite for a true
  strike-*probability* model — as opposed to Task A's damage-*given-a-
  reported-strike* model. This project deliberately does **not** build
  a strike-vs-no-strike classifier without this (or an equivalent)
  denominator. See `README.md` "Scientific limitations".
- **Status:** placeholder only (`configs/data_sources.yaml`, `data/raw/`
  expected filename). No sample fixture exists yet.

## Synthetic data, in general

Every synthetic/sample file in this repository sets:

```
data_origin = "synthetic_fixture"
operational_use = false
```

and is generated deterministically (fixed seed `42`) by
`scripts/generate_sample_data.py`. See `data/sample/README.md` for the
exact fabricated relationships used (e.g. bird size vs. damage
likelihood) — these mirror plausible intuition but are **not derived
from or validated against any real strike or monitoring data**, in
exactly the same spirit as `synthetic_demo/generate_data.py`'s
hand-designed labels.
